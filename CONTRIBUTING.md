# Contributing to AQuA-Architect

Thank you for your interest in contributing to AQuA-Architect. This document provides guidelines and instructions for contributing.

## How to Contribute

### Reporting Issues

- Use GitHub Issues to report bugs or request features
- Include a clear description of the problem or suggestion
- Provide steps to reproduce if reporting a bug

### Submitting Changes

1. Fork the repository
2. Create a feature branch from `main`
3. Make your changes following the guidelines below
4. Submit a pull request with a clear description

### Content Guidelines

- Write in clear, concise language
- Include code examples where applicable
- Follow the existing markdown style and formatting
- Ensure all examples are tested and working

### Architecture Guidelines

- Follow the principles outlined in [architecture.md](architecture.md)
- Reference the [quality checklist](checklist.md) for completeness
- Use the established [scoring rubrics](scoring.md) for evaluation

## Development Workflow

1. **Design Phase** — Use [design prompts](prompts/design.md) to plan changes
2. **Build Phase** — Use [build prompts](prompts/build.md) to implement
3. **Review Phase** — Use [review prompts](prompts/review.md) to validate

## Code of Conduct

- Be respectful and constructive in all interactions
- Focus on the technical merits of contributions
- Welcome newcomers and help them get started

## Questions?

Open a GitHub Discussion or Issue for any questions about contributing.
